## 0. Что делаем и чего не делаем

**Цель.** Сейчас город — это один двор 54×39 м (`scenes/levels/yard.tscn`). Вокруг невидимые стены, за домами
плоская пустая равнина, и мир на горизонте обрывается. Нужен целый микрорайон: город с **объёмом**.

Решения автора:

| Вопрос | Решение |
|---|---|
| Что значит «объём» | **[решено]** 1) город не обрывается: вдали дома, огни, трубы; 2) перепады высот; 3) плотность деталей. Заходимых зданий **пока нет** |
| Размер | **[решено]** целый микрорайон. v1 был ~300×295 м — **слишком пусто**; v2 ужат до **~200×215 м** |
| Плотность | **[решено]** (после первого блокаута) эффект закрытости: **очень узко везде** — проходы 3–5 м, дворики-колодцы 10–25 м, **замкнутые дворы с арками** сквозь дома, дома вплотную, сугробы и брошенные машины. Открытые места **тоже застроены**: проспект узкий (полоса + трамвай + полоса), стадион маленький, пустырь занят стройгородком |
| Структура | **[решено]** вся улица — **одна сплошная сцена** без загрузок. Переходы с затемнением только в интерьеры (подъезд уже есть, остальные интерьеры позже) |
| Привязка к реальности | **[решено]** узнаваемо, но свободно: типовые панельки, проспект с трамваем, школа, гаражи. Планировка придумана под игру. Планировка с картой **принята** автором (v0.1) |
| Названия | **[решено]** названия улиц, вывески и номера домов — **настоящие, с Паскота**. Список даёт автор (см. раздел 4), сами Claude не выдумывает и не подбирает |
| Транспорт | **[решено]** по проспекту ходит **трамвай** |
| Снег | **[решено]** **завалило**: аномальный снегопад, сугробы по пояс, машины под снегом, протоптанные тропинки |
| Юг вдали | **[решено]** балка и огни дальнего района, моря нет |
| Места | **[решено]** проспект с остановкой, школа, пустырь с недостроем, гаражный кооператив, теплотрасса с котельной |
| Края мира | **[решено]** заборы и стены домов + завалы и аварии (машины, трамвай поперёк дороги). Невидимых стен посреди открытого места быть не должно |
| Рельеф | **[решено]** неровная и земля, и постройки: уровни дворов, подпорные стенки, лестницы, террасы |
| Старый двор | **[решено]** пересобрать под новый план: дом Юрчика, гаражи и ларёк переезжают в новый район в новом виде |
| Геймплей | **[решено]** в эту задачу **не входит**: только локация. Враги, предметы, квест и Сергей — отдельной задачей позже |
| Порядок работы | **[решено]** сначала серые коробки (блокаут) на весь район → автор бегает и принимает → потом настоящие модели и свет |

**Не делаем в этой задаче:** врагов, предметы, сценарии, интерьеры (кроме уже готового подъезда), лор.

**Демо MVP не ломаем.** `yard.tscn` и `stairwell.tscn` остаются как есть, главное меню по-прежнему ведёт
в старый двор. Новый район — отдельная сцена `scenes/levels/district.tscn`. Квест MVP переносим туда
отдельной задачей, а старый двор удаляем только после этого.

## 1. Общая планировка

Оси как в текущем проекте: **X — восток, −Z — север, Y — вверх**, 1 единица = 1 метр.
Центр мира (0, 0, 0) лежит в середине района. Играбельная зона: **X −100…100, Z −110…101**.
Шаг Юрчика — 1,7 м/с, бег — 4,6 м/с: по прямой из конца в конец ~45 с бегом, но прямых путей почти нет — петляешь проходами и арками.

**Карта [city_map.svg](city_map.svg) рисуется генератором** (`tools/make_district_blockout.py`) из тех же данных, что и сцены, — поэтому всегда совпадает с блокаутом. Точные координаты — в генераторе, ниже — сводка.

### Уровни земли (главный источник «объёма»)

Район спускается с севера на юг ступенями:

| Высота | Что там | Как связаны уровни |
|---|---|---|
| **+6 м** | Проспект | → двор Юрчика: лестница у остановки и пандус проезда |
| **+3 м** | Двор Юрчика (центр), школа, западный двор | → вниз: **подпорная стенка 3 м** по всей ширине (Z = −15) с тремя лестницами и пандусом проезда |
| **0 м** | Южные дворы, котельная, пустырь | → гаражи: проезд под уклон |
| **−2,5 / −5 / −7,5 м** | Гаражный кооператив, террасами (шаг = высоте гаража 2,5 м) | крыша нижнего ряда гаражей на уровне земли верхнего ряда — по крышам можно пройти |
| **−5 м** | Котлован на пустыре | пандус для грузовиков + приставная лестница |
| **+2 м** | Подземный переход под проспектом | из двора — портал прямо в подпорной стенке (пандус +3 → +2), на северный тротуар — лестница |

Плюс высота от построек: каркас недостроя (3 доступных этажа), теплотрасса на опорах, П-арки труб над проездом,
крыши гаражей, трибуна стадиона. Высокие силуэты над головой: труба котельной 45 м, 16-этажные свечки,
башенный кран, опоры и провода трамвая.

### Ориентиры светом

Ночью игрок ориентируется по цвету света. У каждой зоны свой «цвет», и его видно издалека:

- двор Юрчика — тёплые оранжевые натриевые фонари (как сейчас);
- школа — один холодный белый прожектор над стадионом, мигает;
- котельная — красные огни на трубе;
- недострой — жёлтый прожектор на кране;
- остановка — разноцветные ларьки (вывески-эмиссия);
- гаражи — почти темно, одна голая лампочка у сторожки. Здесь нужен фонарик.

### Петли маршрутов

Петли пригодятся потом: от Сергея нужно уметь уходить, а не упираться в тупик. В блокауте эти петли должны проходиться:

1. двор → арка → «ракушки» → портал перехода → проспект → лестница у остановки → двор;
2. двор → лестница вниз → южные дворы → проезд → котельная → лестница у школы → школа → ворота → двор;
3. южные дворы → лесенка через трубы → гаражи (в том числе по крышам) → стройка → западная лестница → «ракушки» → двор.

Тупики тоже нужны, но короткие: котлован, щели между гаражами, колодец западного двора.

### Декорация: город не обрывается

За краем играбельной зоны идёт кольцо декораций (до ~600 м), куда дойти нельзя:

- **север** — вторая линия 16-этажек и огни окон за проспектом;
- **восток** — ТЭЦ: две трубы с красными огнями, промзона, прожекторы;
- **юг** — балка: тёмный провал, голые деревья, за ней огни дальнего района;
- **запад** — силуэты соседнего микрорайона.

Декорации делаются дёшево: простые коробки с текстурой окон через эмиссию, без коллизий и без теней,
туман их съедает. Ночное небо уже есть (`shaders/city_night_sky.gdshader`), над городом его можно
подсветить заревом.

## 2. Технические правила (для Claude)

Железо автора: **ноутбук, GTX 1650 + Ryzen 5 5600H, 24 ГБ**. Цель — стабильные 60 кадров в окне
1708×960 (внутреннее разрешение 854×480). Каждое решение проверять против этого бюджета.

### Структура файлов

```
scenes/levels/district.tscn          # корень района: окружение, игрок, подсцены зон
scenes/district/terrain.tscn         # земля, подпорные стенки, лестницы, пандусы
scenes/district/z1_prospect.tscn     # по одной подсцене на зону: правки зон не пересекаются,
scenes/district/z2_home_yard.tscn    #   разные сессии могут работать над разными зонами
scenes/district/...                  # z3_school, z4_south_yards, z5_boiler, z6_garages, z7_wasteland, backdrop
scenes/blockout/                     # серые блоки (этап 1)
scripts/levels/district.gd           # extends Level
tools/blender/build_district_*.py    # процедурные модели нового района
```

### Блокаут: как устроены серые коробки

- Один `@tool`-скрипт `scripts/tools/blockout_box.gd` (Node3D). В инспекторе у него размер, тип (жилой дом /
  школа / гараж / граница / проходимая крыша…) и подпись. Сам строит меш + коллизию, красит по типу
  и вешает `Label3D` с названием («9 эт., 4 подъезда»). Автор может двигать и растягивать блоки
  мышью без кода.
- Лестницы в блокауте и в финале: видимые ступени, а коллизия — **наклонная плоскость** (стандартный приём:
  персонаж не цепляется за ступени). Максимальный уклон пандусов и лестниц 35°: `floor_max_angle` у игрока
  по умолчанию 45°, запас нужен.
- Начальную раскладку генерирует Python-скрипт `tools/make_district_blockout.py` по данным зон из этого
  документа (как `tools/make_yard_scene.py`). **После приёмки блокаута источник правды — `.tscn`**:
  скрипт больше не перезапускаем, чтобы не затереть ручные правки автора.
- Каждый финальный ассет делается **с тем же габаритом и точкой опоры**, что его серый блок: замена блока
  на модель не должна сдвигать планировку.

### Земля и рельеф

- Без сторонних аддонов рельефа. Земля — меши из Blender (`build_district_terrain.py`), порезанные на куски
  ~50×50 м (видимость и отсечение по кускам). Коллизия — trimesh. Подпорные стенки, бордюры, лестницы —
  отдельные модульные меши.
- Снег и слякоть на земле: тайлящиеся текстуры (`snow.png`, `slush.png`) с маской через vertex color:
  протоптанные тропинки, слякоть у дорог, чистый снег во дворах.
- **Район завалило снегом [решено].** Это ещё и инструмент планировки:
  - снежный покров — отдельный слой меша поверх земли (~0,3–0,5 м во дворах), в нём «прорезаны» протоптанные
    тропинки и расчищенные проезды; игрок ходит по коллизии покрова, ноги чуть утопают;
  - сугробы по пояс (1–1,5 м) — непроходимые препятствия с коллизией: из них лепятся стенки
    коридоров, тупики и часть границ. Сугробы в рост — у завалов на краях района;
  - машины и лавки — модели «под снежной шапкой» (снег — часть модели, а не декаль);
  - замедление в глубоком снегу и следы — это геймплей, сюда **не входит** (отметить как идею на потом);
  - текущие `drift_long` / `drift_round` — база, нужны крупнее и разнообразнее, плюс снег на козырьках,
    крышах гаражей, перилах и трубах теплотрассы.

### Производительность (обязательно с первого этапа)

- **Окклюзия.** Включить `rendering/occlusion_culling/use_occlusion_culling` (через `set_project_setting`,
  не правкой файла). Дома — `OccluderInstance3D` (коробка по габариту). Панельки идеально перекрывают
  обзор — это главный выигрыш.
- **Дальность видимости.** `visibility_range_end` у мелочи (мусор, лавки, сугробы) — 40–60 м, у машин
  и ларьков — 80 м. Дома видны всегда, у дальних — упрощённые версии (HLOD через `visibility_range`).
- **Бюджет света.** Сейчас каждый фонарь — SpotLight + OmniLight с тенями. Для района это не годится.
  Нужен узел-менеджер `LightBudget`: тени включены только у ~6–8 ближайших к игроку источников, источники
  дальше ~45 м выключены совсем. Вдали остаются только светящиеся ореолы (`lamp_halo.tres`)
  и эмиссия окон — издалека выглядит так же.
- **Снегопад** (`Snowfall`) сейчас висит над двором 70×70 м. Его нужно привязать к игроку/камере.
- **Объёмный туман** оставить, длина 60 м как сейчас. Дистанционный туман — главный способ скрыть дальность.
- **Навигация врагов:** `Level._bake_navigation()` запекает сетку при запуске. Для 300×300 м с ячейкой
  0,25 это будет долго. Когда дойдёт до врагов — запекать заранее в редакторе и хранить ресурсом. Сейчас
  достаточно не мешать этому: всё статичное — на слое коллизий 1, декорации без коллизий.
- После каждого этапа замерять FPS в самой тяжёлой точке (вид с проспекта на двор и школу) и записывать
  в отчёт этапа.

### Проверка из worktree

Редактор Godot с MCP открыт на основном checkout, поэтому `play_scene` правок из worktree не видит.
Рецепт проверки — в памяти проекта («Testing from a worktree»): headless-импорт, затем отдельный процесс
с `--script`, снимок `get_texture().get_image()`. После `--headless --import` вернуть `project.godot`
(импорт выкидывает автозагрузки MCP).

### Инструменты для приёмки (нужны автору с этапа 1)

  в нужную зону.
- Свободная камера (`scripts/tools/free_camera.gd` уже есть) — чтобы облететь район сверху.
- Скриншот-карта: вид сверху на весь район, сохраняется в `docs/screenshots/district_*.png` и сверяется
